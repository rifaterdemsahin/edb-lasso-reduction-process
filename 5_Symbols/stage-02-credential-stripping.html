Credential Stripping

Identifies and masks passwords in conninfo strings, URI connection strings, MD5 hashes, SCRAM-SHA-256 tokens, API keys, and customer portal tokens across all diagnostic artifacts.

Conninfo & Replication Passwords

postgresql.conf, barman.conf

Replication parameters like primary_conninfo and backup connection commands frequently store passwords in plain text.

primary_conninfo = '... password=SuperSecretP@ssw0rd!'
primary_conninfo = '... password=[REDACTED_PASSWORD]'

EDB Customer Support Tokens

os_environment.txt, lasso_metadata.json

Customer tokens used for automated upload must be redacted before sharing diagnostic bundles with open communities or third parties.

EDB_CUSTOMER_TOKEN=edb_prod_cust_tok_98273419084...
EDB_CUSTOMER_TOKEN=[REDACTED_EDB_TOKEN]

SCRAM-SHA-256 & MD5 Secrets

pg_hba.conf, catalog exports

Hashes extracted from authentication catalogs can be susceptible to offline rainbow-table or brute-force attacks if leaked.

host ... repuser ... md58b8b9a5e13d5a4980a312f2c8d23e590
host ... repuser ... md5[REDACTED_MD5_HASH]

Cloud Keys & SSH Credentials

os_environment.txt, barman.conf

Environment variables like AWS S3 backup keys or SSH identity flags are scrubbed cleanly to prevent cloud account compromise.

AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/...
AWS_SECRET_ACCESS_KEY=[REDACTED_SECRET_KEY]
