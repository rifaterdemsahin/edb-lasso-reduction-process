Diagnostic Generation Guide

Create EDB Lasso Tarball (.tar.gz)

Learn how to generate the standardized PostgreSQL diagnostic report from both the CLI and the UI, understand what to expect, and discover the critical security gotchas to watch out for before sharing.

How to Do It From the CLI

Command-line syntax & flags
Terminal

Execute lasso as the postgres or system superuser. We strongly recommend generating the archive offline with --no-upload so it can be reduced before dispatching.

1. Recommended Offline Diagnostic Collection: 
sudo -u postgres lasso \
  -U postgres \
  -d postgres \
  --no-upload \
  -o /var/tmp/edb_lasso_report.tar.gz
2. Targeted Scope (Avoid Large Logs): 
sudo -u postgres lasso \
  -U postgres -d postgres \
  --days 2 \
  -o /tmp/edb_lasso_recent.tar.gz
3. Using PoC Mock Bundle Generator: 
python3 lasso_redact.py \
  --create-mock-tarball mock_lasso_bundle.tar.gz
Requires pg_read_all_settings or superuser privileges.

What to Expect When Creating the Tarball

Clear expectations regarding performance, outputs, and runtime

1. Archive Structure

Produces a single .tar.gz archive containing structured subdirectories: system/, postgresql/, barman/, and metadata.json.

2. Runtime Duration

Typically takes between 30 seconds and 3 minutes depending on disk I/O and how many historical log files are included in the scope.

3. File Size Range

Standard bundles range from 5 MB to 35 MB. If unrotated PostgreSQL log files are bundled without range filters, size can expand drastically.

4. Workload Overhead

Near-zero production impact. Lasso uses lock-free system catalog queries, zero user table scans, and runs at low CPU priority.

What to Care About & Watch Out For (Crucial Gotchas)

Avoid common security pitfalls and operational failures

1. Raw Secrets are Captured Verbatim!

Lasso copies postgresql.conf, pg_hba.conf, and barman.conf verbatim. Plaintext passwords in primary_conninfo, Barman backup passwords, and MD5 hashes will be inside the raw tarball.

Always run the Reduction Process before sending to any external party!
2. Dangerous Log File Bloat

If your cluster generates 20 GB of logs per day and log rotation is disabled, Lasso might attempt to archive the entire log directory, filling up /tmp and crashing the collector.

Always specify: --days 2 or --scope recent
3. Privilege Denials & Incomplete Dumps

Running Lasso as a standard OS user without root or postgres sudo rights causes silent omissions: /proc metrics, sysctl settings, and PostgreSQL catalog queries will be blank.

Always run with: sudo -u postgres lasso ...
4. Egress Firewall Blocks

In locked-down banking or healthcare networks, outbound HTTPS (port 443) to external support endpoints is typically blocked, causing --upload to timeout. Use offline tarball generation and sanitize first.

Offline flag: --no-upload -o /var/tmp/bundle.tar.gz
